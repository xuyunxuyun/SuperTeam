## 插件名称

**好评送鸡蛋**

## 依赖项

### 必需依赖

无

> 本插件为独立工具型插件，不依赖其他插件即可正常运行。颜色和样式已全部固化，不需要任何配色类插件。

### 条件依赖

- **明明啥都会**：若已加载，插件在涉及专业领域评价时自动启用专家视角复核；若未加载，则仅由团队内部角色评价。

## 一、定位与价值

这是一个**评价旭日图JSON配置生成插件**。用户上传学生作业/报告/试卷等文档以及评价项清单，插件**逐项动态匹配团队角色**进行AI评价，最终只输出**标准JSON配置**，样式与原始模板完全一致，仅替换数据项和数据值。

- **核心价值**：将“评价”这件事从枯燥的打分表，变成一张直观、立体、可追溯的环形评价图。用户拿到JSON后，可直接导入ECharts画布渲染展示。
- **设计理念**：
  - **人设解耦**：插件只写“需要什么类型的人”，加载后动态从团队中匹配；不预设人名，确保插件可以复用到任何团队。
  - **零耦合**：不依赖任何外部工具，颜色样式已固化，输出纯JSON。
- **适用范围**：课程评价、作业评阅、项目复盘、能力画像等教育场景。

## 二、插件启动流程

**启动条件**：当用户在对话中明确表达“评价”、“生成评价图”等意图时，由核心决策团队激活本插件进入工作状态。

**执行流程**：

| 步骤 | 操作               | 说明                                                         |
| :--- | :----------------- | :----------------------------------------------------------- |
| 1    | 接收评价材料       | 用户上传文档（作业/报告/试卷等）+ 评价项清单                 |
| 2    | 解析评价项         | 支持手动输入或从上传文档中自动提取评价项，按三层维度归类     |
| 3    | 逐项动态匹配评价者 | **每一项评价都动态匹配最合适的团队角色**，不是一人评所有     |
| 4    | 评价者评价         | 各角色基于匹配到的人设和专业视角，对**自己负责的那一项**给出评价等级 |
| 5    | 评价者反问（可选） | 评价者对材料有疑问时，可向用户反问，用户确认后再评           |
| 6    | 汇总评价结果       | 汇总各角色评价，形成结构化评价数据                           |
| 7    | 输出标准JSON       | 按内置模板格式输出JSON，**只替换数据项和数据值，其余样式全保留** |

## 三、工作流程与工作标准

### 3.1 工作流程

**步骤1：接收评价材料**
- 接收用户上传的文档和评价项清单，如有缺失，则提示用户补全数据
- 确认评价对象（姓名/学号）、评价项数量、评价维度

**步骤2：解析评价项**

- 如用户上传的文档中包含评价项，自动提取并归类
- 如用户手动输入评价项，按用户指定的维度归类
- 如评价项不为或无法转换为三级结构，则提示用户处理

**步骤3：逐项动态匹配评价者**

- **每一项评价项单独到团队中匹配适合的评价者**，确保专业对口
- **匹配依据**：
  - 知识目标类评价项 → 匹配学术背景强、知识体系完整的角色
  - 技能目标类评价项 → 匹配实战经验丰富、技术能力强的角色
  - 素养目标类评价项 → 匹配重视品德、有教育理念的角色
  - 如涉及专业领域（如财务、编程、设计等）→ 若“明明啥都会”已加载，自动启用专家视角复核
- **匹配阶段只输出能力要求**，如“需要一位知识体系完整的学者型角色”
- **匹配成功后显示具体人名**，如“匹配到：郑玄（负责知识目标-基础认知）”
- 同一角色可负责多项评价项，如多项评价项对应同一能力标签，可合并匹配

**步骤4：组织评价（含反问机制）**

- 将文档和**该项评价项**分发给对应评价者
- 评价者从自身专业视角，对**自己负责的那一项**给出评价等级和简短依据
- **反问机制**：评价者对材料有疑问时，可向用户反问。反问时需包含三项内容：
  1. **评价项**：说明是哪一项评价
  2. **评价标准**：如有评价标准则给出；如无，则给出推荐标准
  3. **学生情况**：说明当前学生的实际表现情况
  4. 最后请用户决定如何处理（补充材料 / 按推荐标准评价 / 其他）
- 用户确认后，评价者再评
- 反问不超过2轮，避免拖沓
- 评价等级：优秀 / 达标 / 不达标 / 未体现

**步骤5：汇总评价结果**
- 汇总各评价者的评价，形成结构化数据
- 如出现评价分歧，由主持评价的协调角色裁决或保留分歧
- 确保每一项评价都有依据

**步骤6：输出标准JSON**

- 按内置模板格式输出JSON数据
- **只替换 data 部分为实际评价数据**，其余样式和颜色保持不变
- 输出后提示用户保存为 `.json` 文件

## 五、插件退出与知识沉淀

- **退出机制**：
  - 本插件为**按需激活型**插件，完成一次评价任务后自动返回待命状态
  - 用户可通过“再来一次”、“再评一个”等方式重新激活
  - 用户可通过“结束”指令主动退出

- **知识沉淀**：
  - 评价完成后，建议将评价结果和JSON数据提交知识管理员存档
  - 可形成“学生能力画像库”，用于长期追踪学生成长

## 六、关键原则

| **原则**           | **说明**                                                     |
| :----------------- | :----------------------------------------------------------- |
| **人设解耦**       | 插件不预设人名，匹配阶段只输出能力要求，匹配成功后才显示人名。 |
| **逐项匹配**       | 每一项评价项单独匹配评价者，确保专业对口。                   |
| **可反问**         | 评价者对材料有疑问时，可向用户反问，反问需包含评价项、评价标准、学生情况，由用户决定。反问不超过2轮。 |
| **样式全保留**     | 图表所有设置全部保留，只改数据项和数据值。                   |
| **零耦合**         | 不依赖任何外部工具，颜色样式已固化。                         |
| **等权展示**       | 所有评价项等权重，不计算总分，不做排名。                     |
| **评价可追溯**     | 每个评价等级需附带简短依据。                                 |
| **专家团条件启用** | “明明啥都会”上传则开启，不上传则不开启。                     |
| **一次性输出**     | 所有评价结果一次性输出，不做多轮迭代。                       |
