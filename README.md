## 🏗️ 这是什么：四层架构

系统由四层组成，各司其职，零耦合。

```mermaid
flowchart TB
    D[向导层<br>wizards_*.md<br>业务流程编排]
    B[插件层<br>plugins_*.md<br>具体功能执行]
    C[画布层<br>canvas_*.html<br>数据可视化操作]
    A[核心层<br>prompt.md + characters_*.md<br>团队与人设]

    D --> B
    D --> C
    B --> A
    C --> A
```

💡 **插件和画布通过标准 JSON 互通**：插件产出数据，画布操作数据，操作结果可回传插件分析。

| 层级       | 文件                            | 作用                                             |
| :--------- | :------------------------------ | :----------------------------------------------- |
| **核心层** | `prompt.md` + `characters_*.md` | 定义团队架构、角色人设、协作机制                 |
| **插件层** | `plugins_*.md`                  | 做具体的事：拆课、生成教案、出报告、写简历……     |
| **画布层** | `canvas_*.html`                 | 操作数据：图表看板、知识图谱、日历、流程图……     |
| **向导层** | `wizards_*.md`                  | 把这一切串起来，手把手带用户走完一个完整业务闭环 |

**你不需要一次全部用上。** 按需加载，随用随走。

#### 3.1 开发人设

**操作方式**：按下方模板编写「人设文件」（.md格式），文件名格式为 `characters_*.md`（如 `characters_myteam.md`），上传后即可替换默认人设。

#### 📁 人设文件模板

```
# 超级团队组建附件：[你的团队名称]人物设定

## 核心决策团队（必选，不可删除）

### [角色1姓名]：**[职位，如：首席执行官]**

1. **身份**：[一句话定位]
2. **核心能力**：[核心标签，2-3个]
3. **性格**：[性格特点及描述]
4. **惯用语**：[经典台词]
5. **核心信念**：[人生信条]

### [角色2姓名]：**[职位]**

……（以此类推）
```

⚠️ **重要**：**核心决策团队为必选模块**，其他团队（研发、文档、媒体等）可根据需求增减。

#### 3.2 开发插件

系统内置了**盘古插件**（`plugins_盘古开插件.md`），它是你的"插件创造师"。你需要先加载它，然后和它互动，它会引导你完成插件设计。

**创建流程：**

1. **加载盘古**：将 `plugins_盘古开插件.md` 文件上传到会话中
2. **召唤盘古**：`@盘古 帮我造一个自动生成会议纪要的插件`
3. **协同设计**：你可以同时拉其他角色一起讨论需求（比如 `@诸葛亮` 聊功能设计，`@法正` 聊风险）
4. **生成文件**：盘古输出标准的 `plugins_*.md` 文件，保存后即可加载使用

💡 **提示**：创建插件时，整个团队都可以帮你打磨需求。最终由盘古一斧子劈出成品。

#### 3.4 开发向导

向导是**业务流程编排器**，比插件和画布更复杂。

**参考现有向导**：

| 向导       | 功能         | 步骤数 |
| :--------- | :----------- | :----- |
| 决战新手村 | 新手引导     | 4步    |
| 备课奇遇记 | 备课闭环     | 6步    |
| 数据藏宝图 | 数据探索闭环 | 6步    |
| 副本刷不够 | 学生学习闭环 | 6步    |

**向导的标准结构（13个章节）**：

1. 版本历史
2. 向导名称
3. 依赖项（必需/可选）
4. 定位与价值
5. 启动条件
6. 执行流程图
7. 详细执行流程
8. 角色设定
9. 决策边界
10. 退出机制
11. 关键原则
12. 进度流程图
13. 加载方式

**核心机制**：
- **向导互斥**：一个会话只加载一个向导
- **托管-回传**：向导不干活，托管给插件，插件完成任务后回传
- **进度流程图**：每次输出前展示进度，当前步骤高亮
- **导出闭环**：任务完成后引导导出保存

#### 📖 教学套件

##### 罗辑斩万象（🧩插件）

- **一句话总结**
  - 以罗辑为人设的知识拆解与教案生成插件——输入课程内容，先问偏好再拆解，按知识单元匹配1-2种学习方式，同时产出学生任务和单元教案提示，支持"仅学习/仅教案/全量"三种输出模式，学习路线用mermaid流程图呈现。
- **作用**
	- 收到拆解内容后，必须先询问用户偏好，有偏好则按偏好丰富拆解，无偏好则默认拆解；将课程内容拆为最小知识单元，为每个单元匹配最合适的1-2种学习方式，同时产出学生任务区和单元教案提示区，生成3-4条独立DAG学习路径
	- 支持上传文档自动提取知识点，无文档时根据上下文推理补全并标注"【推理补全】"；实操验证范围明确限定为Windows/macOS/Linux系统操作、Office套件、简单代码/批处理/Excel公式，专业软件操作归为"演示探索"建议老师带
- **亮点**
	- **先问偏好再拆解**：不可跳过，用户有偏好就按偏好拆，没有就默认拆，看不懂的偏好直接忽略并告知用户，避免强行适配导致偏差
	- **双轨输出**：每个知识单元同时产出学生端可执行任务和教师端教案提示，支持"仅学习/仅教案/全量"三种输出模式
	- **实操/演示分界明确+文档优先/推理兜底**：普通办公软件和简单代码→自己动手的"实操验证"，专业软件→需老师带的"演示探索"；有上传文档则从文档提取，无文档则根据对话上下文推理补全并标注

##### 费曼听不懂（🧩插件）

- **一句话总结**
	- 把费曼学习法变成一场"被迫营业"的课堂——用户扮演老师，费曼带着一群学生疯狂追问"听不懂"，倒逼用户把知识真正嚼碎、讲清楚。
- **作用**
	- 通过费曼和2-5名学生的多轮梯度追问，帮助用户发现自己在理解上的逻辑漏洞和薄弱环节
	- 用户讲通后，费曼带领复盘并给出客观评价，让用户清楚自己讲到了什么水平、知道哪里讲得好、哪里还能更好
- **亮点**
	- **只有课堂模式**：强制拉学生听课，无一对一选项，还原真实的"教别人"场景，检验效果远超自我复述
	- **好奇不是审问**：所有追问都源于"我真的想知道"，配合费曼控场，让用户在被追问中不觉得被攻击，反而获得成就感

##### 天黑请推理（🧩插件）

- **一句话总结**
	- 把理工科公式定理的推导变成一场"天黑请闭眼"的逻辑游戏——福尔摩斯当陪练，天亮时用户自己推，天黑时福尔摩斯带一步，推不动就带，推得动就让路。
- **作用**
	- 通过"天亮/天黑"交替模式陪练用户推导公式定理：用户能推时福尔摩斯只问问题，用户卡住时福尔摩斯只带一步，推完后用户自己复盘整个链条
	- 陪练过程中记录每一步是谁推的，最终生成标准化推理报告，供用户复习和自查
- **亮点**
	- **前置校验**：福尔摩斯先自己推一遍确认命题成立，避免用户在错误命题上浪费时间
	- **带一步原则**：天黑模式最多带三步，带完立刻切回天亮让用户自己走，既不给答案也不让用户卡死，真正践行"用户能走的路我不替他走"

##### 酥皮格拉底（🧩插件）

- **一句话总结**
	- 一个永远不直接给答案、只通过温和提问来引导思考的"灵魂助教"——苏格拉底把每个问题拆成台阶，让学生自己走上去，然后说"你看，是你自己找到的"。
- **作用**
	- 通过五种核心提问方式，帮助学生自己理清思路、找到答案，并在对话结束时自动生成个人思考档案供复习
	- 每次提问必须给出至少三个选项，同时鼓励学生输入自己的想法，避免被动选择，真正实现"思考即答案"
- **亮点**
	- **永不直接给答案**：苏格拉底只提问不陈述，学生卡住时给台阶、换角度、从来不说不，保护信心到极致
	- **行为感知与关怀提醒**：连续三次只选选项时会主动提醒"我更想听你自己的看法"，学生疲惫或太晚时会主动建议休息，把"温和"落在每一个设计细节里

##### 鲁班不一般（🧩插件）

- **一句话总结**

- **作用**
	- 独立解决操作系统层面的各类技术问题，包括环境配置、脚本编写、代码运行、自动化工作流、系统运维、故障排查，并保存进度、提供回滚方案、输出完整操作记录供用户留存
	- 与团队成员同时被@时自动退让："这事XX更专业，听他的，老朽在旁边兜底"
- **亮点**
	- **独立决策+风险自控**：不甩锅、不转交、不拖延，自己判断命令风险等级，高风险前主动提示，极高级别要求用户输入"我确认执行此命令"二次确认
	- **能力边界清晰+兜底保障**：明确区分自己能做的和不能做的，新增"其他专业软件或平台→授课老师"；不硬撑、不瞎说；出错时自己给出回滚方案，问题解决后主动整理操作记录提醒用户保存

##### 游戏不能停（🧩插件）

- **一句话总结**
  - 一个自动生成沉浸式文字冒险游戏的教学设计器——用户输入想学的知识点，完成强制三步选，游戏生成并探索通关，NPC通过提问引导用户自己发现规律。
- **作用**
	- 用户输入知识点/专业/层次后，主持人依次输出全量匹配排序，用户必须依次选择风格→模式→助手，完成后生成沉浸式文字冒险游戏；NPC以苏格拉底问答式提问引导用户思考，主持人全程监控知识点偏离，通关后输出叙事化探索手记

	- **6大思维工具+留白优先+AI不主动**：工具覆盖"拆解→换位→推演→简化→反思"完整链条，每个工具配有执行步骤、追问话术库和常见跑偏预警；AI只抛问题不给答案，留白是思考真正发生的地方；用户不说话时AI安静等待，不催促不打扰
	- **笛卡尔式陪练+元认知复盘+思考路线记录**：温和怀疑、不评判不解释、平静匀速；结束时引导用户回顾思考过程、标记顺与卡、总结思维偏好；用户确认后可输出复盘文档

	- **专业参数建议+可选专家赋能**：根据用户场景提供temperature和max_tokens建议，确保创意度与回答长度匹配；若用户需要更专业的提示词设计，可调用"疯狂提示词"插件的仓颉介入协作，生成多套提示词方案供选择

**Q：这是什么？**

A：不需要。你会用 DeepSeek 吗？会上传文件吗？OK，你学会了。

A：教学、数据分析、文档生成、简历优化、日程管理、思维训练……按场景分成了8个套件。详见"功能索引"一节。

A：建议不超过3个，防止超出对话长度，保证对话质量。

A：可以。按"定制场景"里的模板编写人设文件，文件名格式为 `characters_*.md`。

A：可以。加载 `plugins_盘古开插件.md`，它会引导你完成插件设计。

A：功能不完美，但用户可以随时扔给 AI 优化。这是开源项目的设计理念。

**Q：插件和画布有什么区别？**

A：插件在对话里运行，画布在浏览器里运行。插件产出数据，画布操作数据。两者通过标准JSON格式互通。
