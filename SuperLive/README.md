## 🧭 先理解一件事：这是“作品的生产线”，不是“工具集合”

超级现场不是“三个工具的菜单”，是一条**从原料到成品的加工线**：

- **原料**：一份资料或一个需求。
- **加工**：搭台看大戏设计剧情、生成 JSON，七星锦囊铺校验配包，铜雀老戏台播放消费。
- **成品**：一个可运行的 zip 数据包，以及用户走完剧情后导出的作答记录。

**三件套缺一不可**：没有搭台看大戏，就没有剧情包；没有七星锦囊铺，包是散的、校验不过的；没有铜雀老戏台，包跑不起来。**它们是上下游，不是并列选项。**

## 🎭 三件套详解

### 搭台看大戏（🧩 插件）

- **一句话**：剧情包全自动生产线——用户提供资料或需求，插件负责设计剧情、串联场景、逐关确认、生成 JSON、输出图片清单和文生图提示词。
- **作用**：CEO 接管主持，按任务特性动态匹配职位，走四关口：
  1. **剧本蓝图**：剧情大纲、人物提取、分支结构选择（汇合式/树状/混合式）、分镜分场景、Mermaid 拓扑图 + 文字说明，用户确认。
  2. **内容定稿**：对话设计、描述撰写、选项设计、润色，用户确认。
  3. **内部校验**（用户不可见）：格式合规 → 路径逻辑 → 用户视角 → 合规风险，不通过打回关口 2 重做，不打扰用户。
  4. **技术方案**：init 要做的事、result 结算方式、图片清单提取、风格确认、大模型选择、回退支持、人物位置，用户确认。
  5. **逐个产出**：按编号逐个生成 script（每个单独确认），最后统一生成 init 和 result，最后统一输出图片提示词。
- **亮点**：
  - **四关口流程 + 内部校验不打扰用户**：每关用户确认后才推进；内部校验在关口 2 之后由团队自己查，不通过打回关口 2 重做。
  - **职位动态匹配 + 规范内置**：插件不写死任何人名，每次按任务特性从团队中动态匹配职位；完整 JSON 编写规范以 markdown 形式内置，生成时随时查阅，输出零异常。

### 七星锦囊铺（🎨 画布）

- **一句话**：剧情包装配与打包工具——上传剧本 JSON 后自动校验格式与逻辑、可视化查看剧本 DAG 流程图、逐项上传图片素材，最终一键打包成可运行的 zip 数据包。
- **作用**：
  - **上传与验证**：支持上传 init.json（可选）、script_XX.json（至少 1 个）、result.json（可选），自动校验文件命名、JSON 语法、场景引用、next 指向、pathType 合法性、needsResult 与 result 匹配等，错误/警告/通过三色分级展示。
  - **剧本流程**：DAG 图展示场景拓扑，节点可自由拖动，点击节点可查看和编辑场景名、背景、描述、角色、对话、输入、选项等字段。
  - **图片素材**：自动从剧本中提取所有图片需求并按类别分组，逐项上传 PNG，实时显示进度。
  - **打包下载**：所有校验通过后一键打包 zip，打包前提示缺图情况。
- **亮点**：
  - **三标签页工作流 + 自动校验**：上传验证 → 剧本流程 → 图片素材三个标签页线性推进，底部状态栏汇总 JSON 数量、图片进度和整体状态。
  - **DAG 可视化 + 图片需求自动提取**：场景以层级 DAG 展示，节点颜色区分起始/输入/结算，布局完成后可任意方向自由拖动；图片需求自动扫描提取，按背景/立绘/道具分组并记录使用位置，支持按文件名自动匹配上传。

### 铜雀老戏台（🎨 画布）

- **一句话**：交互式剧情播放引擎——上传 zip 数据包后，按剧本 JSON 中的场景、对话、输入、选项逐段推进，支持背景与立绘渐变过渡、物品栏查看、回退上一步、结算评估与作答导出。
- **作用**：
  - 上传 zip 后自动解压读取所有 JSON 和 assets 图片，按 init.json 的 actions 执行初始化，支持多剧本选择；进入场景后按“描述→对话→输入→选项”推进，描述和对话点击或空格翻页，输入框 Enter 提交，选项点击跳转。
  - 支持背景交叉淡入淡出、立绘按 appearAt 时机出现并支持 sprite/hide 动态控制、物品栏点击查看道具详情、allowRewind 开启后可回退上一步；走到 isEnding 场景触发结算，加载 result.json 执行 judgeCase/computeScore/renderTree 等动作，生成评估结果、画像星级、雷达图，并自动追加作答导出按钮。
- **亮点**：
  - **交互式剧情播放 + 视觉过渡**：背景双层交叉淡入淡出，人物立绘按 appearAt 时机出现，sprite/hide 支持对话级动态换装和隐藏，立绘带 10px 边缘渐变淡出效果；支持完整回退栈，可逐步退回任意历史状态。
  - **结算评估 + 作答导出闭环**：支持 judgeCase 情形判定、computeScore 画像分数计算、renderTree 渲染评估结果、condition 条件分支；自动追加作答导出按钮，导出内容含用户信息和完整时间轴作答记录。

## 📦 剧情包规范（摘要）

完整规范见 `搭台看大戏` 插件附录 A，这里只列骨架。

```
pack.zip
├── init.json          初始化（可选）
├── script_01.json     剧情（必需，至少一个）
├── script_02.json     剧情（可选，按编号排序）
├── result.json        结算（可选，被 needsResult 的剧情引用）
└── assets/            图片目录（强制）
    ├── BG01_xxx.png   背景 16:9
    ├── CH01_xxx.png   人物立绘 3:4，透明 PNG
    └── IT01_xxx.png   道具 1:1，透明 PNG
```

**硬性规则**：
- `script_` 后必须是两位数字（`script_01.json`，不是 `script_1.json`）。
- 所有图片必须放 `assets/`，JSON 中引用写 `"assets/文件名"`。
- 图片扩展名与实际文件一致，本项目统一 `.png`。
- 至少一个场景 `isEnding: true`，`ending.needsResult` 必须声明。
- 第一个 `renderTree` 必须 `append: false`，后续才用 `append: true`。
- 如果剧本用了 `pathType`，只用三个合法值：「安全路径」「错误路径」「灰色选项」；不做路径判定可以不写。
- `judgeCase` 必须显式处理 `caseRule == null` 的情况。

## ❓ 常见问题

**Q：超级现场和超级团队什么关系？**
A：超级现场是超级团队的二级项目，依赖父项目的插件、画布、人设和向导运行，但拥有独立的设计资产（见 `NOTICE.md`）。

**Q：超级现场有向导吗？**
A：没有。流程编排由父项目的向导层承担，向导文件归父项目本体所有。

**Q：三件套必须全用吗？**
A：如果只是想播放现成的剧情包，可以跳过搭台看大戏和七星锦囊铺，直接用铜雀老戏台。但如果是自己生产剧情包，三件套缺一不可——生产、配包、播放是上下游。

**Q：图片素材必须用 AI 生成吗？**
A：不一定。搭台看大戏会输出文生图提示词，但你可以用任何工具生成，只要符合规范（背景 16:9、立绘 3:4 透明 PNG、道具 1:1 透明 PNG）并放进 `assets/` 即可。

**Q：剧本包里可以有多个剧本吗？**
A：可以。`script_01.json`、`script_02.json`……按编号排序，播放时会弹出剧本选择器让用户选。

**Q：剧情包能商用吗？**
A：剧情内容归制作者所有，非商业用途无需授权；连同本系统引擎/规范用于商业用途需商业授权。详见 `NOTICE.md` 第二、六条。
